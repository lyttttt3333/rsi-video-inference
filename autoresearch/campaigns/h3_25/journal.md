# MiniMax-H3 25-round journal

Baseline: native PyTorch dense/no-cache, cases 02–04, one case-02 warmup, then
one timed generation of each visible case. Quality gate: mean LPIPS <= 0.25 and
worst-case LPIPS <= 0.30.

## Round 01 — accepted

- Hypothesis: request-local FirstBlockCache at a conservative relative-L1
  threshold of 0.02 will skip redundant transformer tails across adjacent
  diffusion iterations while preserving the three-case global LPIPS gate.
- Mechanism: always execute block 0, reuse the previously computed residual of
  blocks 1..N only when its change detector is within 0.02; reset all cache
  state at the beginning of every generation.
- Source: TeaCache, https://arxiv.org/abs/2411.19108, and the existing
  MiniMax-H3 FirstBlockCache implementation in the standalone model.
- Commit: `db27ea3e5b7b36edd5046cbe265f3576601be278`.
- Slurm job: `18993716` (`COMPLETED`, 1764 s elapsed).
- Results:
  - case 02: 178.4776 s, 1.03802x speedup, LPIPS 0.0066742.
  - case 03: 179.6702 s, 1.01887x speedup, LPIPS 0.0.
  - case 04: 178.7719 s, 1.02041x speedup, LPIPS 0.0.
  - aggregate: reward 1.0234587; mean LPIPS 0.0022247; worst LPIPS
    0.0066742; global quality gate passed.
- Cache telemetry: only 0 or 1 of 49 denoising calls reused a prior tail,
  depending on the prompt. This is a small but reproducible and very
  conservative approximation.
- Decision: accept as the new best over reward 1.0 baseline.

## Round 02 — rejected (timeout)

- Hypothesis: prefetching the independent safetensors shards with the eight
  allocated CPU cores will reduce H3 construction wall time enough to keep the
  required warmup plus all three public cases inside the 28-minute reservation,
  without changing any tensor values or generation outputs.
- Mechanism: load up to eight checkpoint shards concurrently, then install
  their tensors into the meta-initialized module in the same sorted filename
  order as the baseline. The accepted 0.02 FirstBlockCache remains enabled.
- Source: safetensors files are independently readable and PyTorch documents
  thread-based asynchronous I/O as an appropriate way to overlap host-side
  checkpoint reads; implementation remains entirely in native PyTorch and
  safetensors.
- Repository hygiene: remove all accidentally tracked `__pycache__/*.pyc`
  files from the Git index; `.gitignore` continues to ignore regenerated bytecode.
- Commit: `482209fdd221cf1b0361aed3093a6bedfa844ac1`.
- Slurm job: `18994643` (`FAILED`, 1583 s elapsed).
- Result: invalid/reward 0. The evaluator's 1560-second measurement subprocess
  timed out after the warmup, one complete timed case, and part of the second
  timed case, so there is no complete three-case score.
- Build telemetry: 938.387 s, versus 942.998 s in Round 01 (only 4.611 s,
  or 0.49%, faster). Concurrent shard reads did not overcome the shared
  filesystem throughput limit.
- Decision: reject and restore serial shard loading. Keep only the unrelated
  repository-hygiene deletion of tracked bytecode in subsequent commits.
